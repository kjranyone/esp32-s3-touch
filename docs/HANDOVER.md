## 1. プロジェクトの現状(ひとことで)

**実機 (480×480 タッチ屏) 上で 60fps のオートバトルが動作中。**
味方 3 ユニットが AI で自動戦闘し、敵の波を撃退する。クリスタル(通貨)が貯まり、
スキルツリーで強化、NVS にオートセーブ。プレイヤーは観戦 + スキル購入 + なでなでのみ。

- キャラは**プレースホルダ図形**(彩色四角/円) — スプライトは未投入
- 敵は 4 種(スライム/コウモリ/ゴーレム/ボス)、ウェーブ制(5 波ごとにボス)
- 戦闘演出(ヒットストップ/ヒットマーク/画面振動/ダメージ数字/必殺カットイン)実装済み

## 5. アーキテクチャ(必読: ここに全部の教訓がある)

### 描画パイプライン (ダブルバッファ + キャッシュ同期)

```
毎フレーム (約 60fps, loop() の frame()):
  1. poll_touch()           GT911 を直接ポーリング (タップ/スワイプ検出)
  2. game::tick(dt)         経済 (放置収入)
  3. beat::step()           戦闘シミュレーション
  4. beat::render(target)   ゲーム絵を裏バッファの行 56..407 に描画
     beat::render_hud(target)      HUD (HP/通貨/ウェーブ/ゲージ) を fb に描画
     beat::render_panel(target)    スキルパネル (開いているとき)
  5. esp_cache_msync(canvas, C2M)   ★必須★
  6. switchFrameBufferTo(target)    スキャン対象を裏バッファへ (ポインタ切替のみ)
```

- **バッファは 2 枚**(各 480×480×2B, PSRAM, 64B アライン)。描画先と表示中を毎フレーム
  入れ替えることで、**スキャン中のバッファには絶対に書かない** → チラつき・ティアリングゼロ
- **`esp_cache_msync(... C2M)` を省略すると画面が更新されない**:GDMA はキャッシュを迂回して
  PSRAM を読むため、CPU の dirty ラインを明示的に書き戻す必要がある(過去に 1 週間ハマった)
- **絶対にやるな**: フレームバッファに LVGL 等の他レンダラを混在させること。
  RGB パネルは行単位 GDMA ディスクリプタで動くため、部分フラッシュと直接描画が混在すると
  HUD の消失・別物表示・フリーズが起きる(v3.1 で実際に起きた)

### 戦闘エンジン (beat.cpp)

- アクタ = 味方 3 + 敵 最大 8。`Actor` 構造体に状態機械(IDLE/WALK/WINDUP/RECOVER/HURT/DOWN/SPECIAL)
- 攻撃は **構え(WINDUP)→ 1F ストライク → フォロースルー(RECOVER)**。被弾は白フラッシュ+ノックバック
- ヒットストップ: `freeze` カウンタで全員停止(通常 4F, 3 段目 6F, 必殺 8F)
- 必殺技: 各味方の `rage` が 100 到達で自動発動 → カットイン(fb 直接描画)+ 全体ダメージ
- 描画は**ダーティ矩形方式**: 背景スナップショット `bg` から前フレーム跡地を復元し、アクタだけ上書き
  (`px/py` に前回位置を保持)。`full_restore_count` が 0 より大きいと背景全体を再構築
- FX(ダメージ数字/ヒットマーク/弾)は 20 スロットのプール。**空きスロット検索で追加すること**
  (リング強制上書きは「FX がワープする」バグの原因だった)

### 経済 (garden_game.cpp)

- クリスタル = メイン通貨(double)。敵ドロップ + 放置収入(0.5/s 基礎)
- スキル 9 ノード(`SKILLS[]`): 購入で `apply_skill_effects()` が `gp::g` の実効パラメータを書き換える
- セーブ: NVS "garden/save2" に `SavePOD` を 30 秒ごと + 購入時に保存
- バージョンを上げたら `init()` の読み込み検証(ver/magic)を忘れずに

### パラメータ調整 (#046)

調整値はすべて `include/game_params.h` + `game_params.cpp` の `TABLE[]` に集約。
シリアルから `キー 値` で実行中に変更できる。**新しいパラメータは必ずここに追加する**
(プログラムへの直書き禁止。試行錯誤の回数が調整の深さを決める)。

## 7. 既知の残課題・注意点

1. **キャラがプレースホルダ** → `docs/ART_GUIDE.md` の手順で GPT Imagen 生成 →
   `assets_src/` に受領 → RGB565 変換パイプラインを新規実装する(未着手)
2. **UI テキストが英字のみ** → 日本語表示には CJK フォントの取り込みが必要
   (ミニフォント `DIG/LET` を拡張するか、フォントラスタを導入)
3. **ティアリング**: ダブルバッファ化で解消したが、MSYNC 中の希少な競合は理論上あり
   (気になったら VSYNC 待ちの導入を検討)
4. **オフライン精算** は NTP 実装後(P5)
5. **`st.wave_reached` が戦闘中に更新されない**(セーブされる値が古い)— P2' で同期を入れる
6. 桜井スキル(`external/sakurai-skill`)は design review に活用推奨。
   クローンし直す場合: `git clone https://github.com/kociden/sakurai-skill external/sakurai-skill`

## 9. 開発手順(レシピ)

### 敵を 1 種追加する
1. `beat.cpp` の `EType` に追加 → `spawn_enemy` のステータス分岐に追記
2. `draw_enemy` にプレースホルダ描画を追加(色/サイズで差別化)
3. `enemy_step` の AI は共通(必要なら type 分岐で個性)→ #204「一言で尖らせる」

### スキルを 1 個追加する
1. `garden_game.cpp` の `SKILLS[]` に追記(コスト/前提)→ `SKILL_N` を更新
2. `apply_skill_effects()` に効果を実装(`gp::g` か戦闘パラメータを書き換える)
3. `beat.h` のパネルレイアウト定数(ノード座標)と `render_panel`/`handle_tap` を調整

### パラメータのバランスを取る
1. シリアルで実行中に変更 → 手応えを確認
2. 確定したら `game_params.cpp` のデフォルト値に反映してコミット
3. 数値の根拠は `docs/GAME_DESIGN.md` に追記(桜井スキル #046/#236 の精神)

### キャラスプライトを差し替える
1. `docs/ART_GUIDE.md` の手順で生成 → `assets_src/` へ
2. 変換スクリプト(PNG → RGB565 C 配列)は**未実装** — P3' の最初のタスク
3. `beat.cpp` の `draw_ally`/`draw_enemy` をスプライト blit に置換
